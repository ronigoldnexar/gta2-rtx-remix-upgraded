## 4. Parallel plan for the 8x L4 host

Resources on that host: with 48 vCPUs, `GTA2_SLOTS=21`, `GTA2_LOAD_MAX=72`, `GTA2_MEM_MIN_GB=6` (192 GB RAM
gives ~60 game sessions' worth, so CPU is the limit), the player's page on the top 3 cores, Remix pinned to GPU 0,
generation (SDXL, TRELLIS, map generation) on GPUs 1-2, game containers round-robin over GPUs 3-7
(`--gpus device=N`). Concurrency cap: 20 agents, of which at most 12 need game slots, 4 use generation GPUs,
the rest offline. One run at a time per agent; builds `nice -n 10 make -j8` under the build lock.

Every agent: one objective, an owned file set, a verification with frames or numbers, a commit per stream
with a comment on its issue, shared runner libraries frozen (mission logic in `gamerun/missions/<job>.py`),
never touches `repo/stage` (only `restage.sh`), never puts a shell variable in an `rm` command, never uses a
Monitor tool, polls with bounded loops.

## 6. Incidents and lessons (also on issue #10)
- Overload (8 Nov ~17:05 UTC): 20 agents, 6 slots, 2 play containers, `make -j8` builds, SDXL/TRELLIS, a headless browser and encodes on 8 CPUs / 31 GB: load 68, memory exhausted, the session and every container died; the NVIDIA driver was left unable to allocate (Remix "Failed to create fence" for the rest of the day) until the kernel modules were reloaded. Caps and gates now exist (section 1, process). On a big host the same caps scale by core count; they must not be removed.
- Unverified stage on the play page: a clean checkout has no art, so a stage built from it drew untextured figures; the gate in `restage.sh` and `play.sh` prevents a repeat.
- Agents hang forever on `rm` with a shell variable (harness safety prompt); agents that end a turn on a Monitor sometimes never wake; agents committing from clean checkouts diverge the local branch (realign with stash/reset/pop; one conflict today).
- QA3's district sweeps measured Downtown because the harness never swapped the level; the swap now verifies itself.
